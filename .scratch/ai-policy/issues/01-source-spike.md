# Source verification spike

Status: resolved
Type: research

For each candidate source in `../spec.md`, find out whether it can feed a daily, code-rendered policy diff:

- Access: endpoint/feed URL, auth (key? how to get one, cost), rate limits, terms of use for automated access.
- Shape: which fields exist — the ones the design needs are a stable item id, a stage/status, a date of the latest action, a title, a link, and for rules/consultations a deadline.
- Diffability: can a daily run ask "what changed since <date>" (an updated-since filter, change hashes, an RSS feed), or does it need to snapshot and compare?
- Filtering: how well a keyword query (e.g. "artificial intelligence") separates AI items from noise, measured on one real recent week: items returned, and roughly how many are truly about AI policy.
- US states: LegiScan vs Open States — which one gives the "passed a chamber" stage most reliably.
- EU: which of OEIL / EUR-Lex / Commission press / EDPB / AI Office / "Have your say" has a machine-readable feed; which need HTML scraping.
- News & commentary: shortlist of authoritative EU/US AI-policy outlets with an RSS/API, paywall status, and post volume per week.

Output: a table per source plus a recommendation (use / use with caveat / drop), under `## Answer`.

## Answer

Spike run 2026-10-13. Keyless endpoints were called directly. Congress.gov and Regulations.gov were called with api.data.gov's public `DEMO_KEY`, which needs no signup. Open States and LegiScan were not called with a key: their parts come from docs, the public OpenAPI schema and one secondary source. Anything marked _unverified_ was not read or run. "Noise" means keyword hits versus items that are actually about AI policy, judged from titles.

### US federal

**Federal Register API**: use with caveat.

| Aspect           | Finding                                                                                                                                                                                                                                                                                                                                                                  |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Access           | `https://www.federalregister.gov/api/v1/documents.json`. No key, no rate-limit headers in the response. The developer docs page now returns a "Request Access" wall to non-browser clients ("aggressive automated scraping"), but the API itself answered. Limits and ToS: _unverified_.                                                                                 |
| Fields           | `document_number` (stable id), `type` (Rule / Proposed Rule / Notice / Presidential Document), `publication_date`, `comments_close_on` (deadline; e.g. Copyright Office "Music Streaming Fraud" → 2026-11-23), `effective_on`, `docket_ids`, `regulation_id_numbers`, `significant`, `html_url`, `agencies`, `presidential_document_type`. Select them with `fields[]=`. |
| Diff             | `conditions[publication_date][gte]=<date>`. Documents are immutable, so the daily diff is "published since the last run".                                                                                                                                                                                                                                                |
| Noise (measured) | `conditions[term]="artificial intelligence"` is a full-text search. **7 days: 6 hits, 0 about AI policy** (crypto rules, SEC adviser rules, Sea Grant meeting). **90 days: 96 hits, 1 with AI in the title** (NIST NVD RFI). Full text catches every document that mentions AI in passing.                                                                               |
| Recommendation   | **Use with caveat.** It is the canonical source for rules, EOs and comment deadlines, but keyword discovery is mostly noise. Take the term hits only when the title or abstract matches, add `conditions[presidential_document_type]` for EOs, and track watchlisted dockets/RINs. Let Jev judge the remainder.                                                          |

**Congress.gov API**: use with caveat (needs a key).

| Aspect           | Finding                                                                                                                                                                                                                                                                                                                                                                                                           |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Access           | `https://api.congress.gov/v3/bill?fromDateTime=…&toDateTime=…&sort=updateDate+desc&limit=250`. Free api.data.gov key; the LoC GitHub README states **5,000 requests/hour**. `DEMO_KEY` worked but returned `X-Ratelimit-Limit: 10`.                                                                                                                                                                               |
| Fields           | List items: `congress`+`type`+`number` (stable id), `title`, `originChamber`, `introducedDate`, `latestAction{actionDate,text}`, `updateDate`, `url`. Structured stage (action codes, `/actions`, `/laws`) is on per-bill sub-endpoints, which cost one request per bill (sub-endpoint contents _unverified_). No deadlines.                                                                                      |
| Diff             | `fromDateTime` filters on `updateDate`. **Caveat:** `updateDate` also moves on text, cosponsor and metadata changes. Of the 16 AI-titled bills "updated" 2026-10-06..13, **only 2 (HR 10768, HR 10752) had a `latestAction.actionDate` in the window**. Fetch by `updateDate`, then report only when the stored `latestAction` (date + text) changed.                                                             |
| Noise (measured) | The API has no keyword search, so filtering happens client-side on titles. 7 days: **1,189 bills updated** (5 pages of 250); **16 had AI terms in the title**, all genuinely AI bills. Almost all were referrals, though: HR 9501 was placed on the Union Calendar and HR 6875/HR 2385 were reported. Title matching misses AI provisions inside non-AI bills (NDAA, appropriations): put those on the watchlist. |
| Recommendation   | **Use with caveat.** Discover by title, then gate on stage: report from "reported by committee" or "passed a chamber" onward, plus anything on the watchlist. Introductions and referrals would add about 10/week of noise.                                                                                                                                                                                       |

**Regulations.gov API v4**: use with caveat (needs a key).

| Aspect           | Finding                                                                                                                                                                                                                                                                                                                                |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Access           | `https://api.regulations.gov/v4/documents?filter[searchTerm]=…&filter[lastModifiedDate][ge]=…`. Free api.data.gov key (GSA docs point to api.data.gov rate limits; the 50/min, 500/h figures quoted there are for the _comment POST_ API). The GET limit for a real key is _unverified_. `DEMO_KEY` returned `X-Ratelimit-Limit: 10`.  |
| Fields           | `id` (e.g. `NIST-2026-0100-0001`, stable), `documentType`, `subtype`, `postedDate`, `commentEndDate` (deadline), `openForComment`, `withinCommentPeriod`, `title`, `agencyId`. The `meta.aggregations` block buckets comment end dates (next 3/7/15/30/90 days), which suits the Upcoming deadlines section.                           |
| Diff             | `filter[lastModifiedDate][ge]` and `filter[postedDate][ge]` both work.                                                                                                                                                                                                                                                                 |
| Noise (measured) | 7 days (`lastModifiedDate`): **24 hits, about 2–3 AI-relevant** (NIST "NVD in the Age of AI" RFI closing 2026-10-14; CFTC "Compute Derivatives"). 7 of the 24 were FDA "Supporting & Related Material" attachments. One 2023 ED notice also appeared (old document, recent modification).                                              |
| Recommendation   | **Use with caveat.** Restrict `documentType` to Notice / Proposed Rule / Rule and send the rest through Jev. Its main value is `commentEndDate` for deadlines. It overlaps heavily with the Federal Register: the same NIST, Copyright Office (COLC) and SEC items appeared in both. Join them on docket id to avoid double-reporting. |

**LegiScan API**: use with caveat (pending a live check).

| Aspect         | Finding                                                                                                                                                                                                                                                                                                                                                                                                    |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Access         | `https://api.legiscan.com/?key=…&op=…`. **Key required** (a bad key returns `{"status":"ERROR"}`). Free Public tier, quoted as **30,000 queries/month** (LegiScan homepage per search snippet, apis.io) **and 10,000/month** (other LegiScan pages per a secondary guide): _unverified_ which applies. legiscan.com docs answered 403 (Cloudflare challenge) to this host, so the API manual was not read. |
| Fields         | `bill_id` (stable), `number`, `change_hash`, `status` (values include Introduced / Engrossed / Enrolled / Passed / Vetoed / Failed; numeric codes _unverified_), `last_action_date`, `last_action`, `title`, `url`. | Recommendation | **Use with caveat.** The monthly quota is the constraint: 50 states × master list daily ≈ 1,500 calls/month before any `getBill`. That fits even at 10k, but leaves little room. ### Overall recommendation

- **EU:** EUR-Lex/Cellar SPARQL (adopted and published acts), the EP Open Data API per watchlisted procedure (stage events; feed discovery only once `/procedures/feed` stops returning 500), Have your say (consultations and deadlines), the digital-strategy RSS (AI Office news) and the EDPB RSS (through Jev). Drop OEIL HTML and the press-corner RSS.
- **US federal:** Federal Register (rules, EOs, comment deadlines), Congress.gov (title discovery, gated at "reported" or later and diffed on `latestAction`, not `updateDate`), Regulations.gov for `commentEndDate`, deduplicated against the Federal Register by docket id. Keyword discovery is noisy in both FR and Regulations.gov, so the watchlist and Jev carry the selection.
- **US states:** request both keys and run a one-week side-by-side of passed-chamber events before picking one. Open States has structured action classification and `latest_passage_date`; LegiScan has `change_hash` diffing and an `Engrossed` status but a monthly quota (10k or 30k, unclear).
- **Keys to request:** api.data.gov key (Congress.gov and Regulations.gov; whether one key serves both is _unverified_, request via each site's signup if not), Open States/Plural key, LegiScan Public key. Federal Register, EUR-Lex SPARQL, the EP API, Have your say and all RSS feeds need no key.
