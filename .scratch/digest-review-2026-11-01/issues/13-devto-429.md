# 13: Dev.to rate-limits tag fetches

Status: done
Findings: 13 [low], see `../review.md`

## Problem

Run 41278370156: Dev.to returned HTTP 429 for tags `llm`, `langchain`, `openai`; 11 articles still came through from the others. Check whether tag requests run in parallel and whether a sequential fetch or a retry on 429 (with `Retry-After`) avoids it.

## Comments

### Decision (2026-11-01)

Fetch tags one at a time; on 429 retry once after Retry-After (capped).

### Done

Cause: `fetchDevtoData` fetched the five tags in parallel (`Promise.all`), which Dev.to rate-limits. Change (`src/sources/devto.ts`): tags are fetched one at a time; a 429 is retried once after `Retry-After` seconds (default 1 s, capped at 5 s). Test (`src/__tests__/sources/devto.test.ts`): mocked fetch, 429 with Retry-After 2 then 200: no retry before 2 s, the article kept, one request in flight at a time.
