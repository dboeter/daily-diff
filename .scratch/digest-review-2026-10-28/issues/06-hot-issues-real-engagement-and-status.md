## What to build

A hot issue on the agents page is one people engaged with, and the row says what it is and whether a fix exists. On 2026-10-28:

- Gemini #15404, a 10-month-old antivirus false positive, qualified on +3: two `gemini-cli[bot]` comments and one "/assign". Its row hid the `area/security` label it qualified on, while both Hermes rows showed "security".
- Hermes #145452 (one user's open P3 report) became Highlight 3 and a `highlights.json` entry stated as fact ("Hermes Agent leaks valid `OPENAI_API_KEY`…"); its open fix PR #145478 was not mentioned.
- OpenCode #59387, the maintainers' "Free tier issues: read this first" thread (answer: update to v2), was framed as a live bug from a 300-char body excerpt.
- Every row's count parenthetical took a different form (A9), because the model writes it.

- [x] Comments by bots (`user.type == "Bot"`, `[bot]` logins) and bare slash commands (`/assign`) do not count toward the gain
- [x] Code renders each row's counts and qualifying label in one form; the model writes only the description
- [x] The prompt gets enough of the body to tell a tracking or announcement thread from a bug report (template boilerplate stripped, as ticket 02 does for release notes)
- [x] Decision: whether to fetch fix status (a linked open or merged PR) per shown issue, within the core-call budget in AGENTS.md; if yes, the row shows it
- [x] A Highlight drawn from an open issue is worded as a report ("users report", "an issue says"); decide whether code can check this or the prompt rule stays the only guard, and record the choice
- [x] Tests: a bot comment and a "/assign" add nothing to the gain; the rendered row shows the label
