1: New streaming queries in real-time mode use real-time watermark propagation by default; stateful operators advance the event-time watermark within a batch, so late events are filtered against the live watermark and state is evicted sooner. Queries restarted from an existing checkpoint keep their original behavior, and to keep the previous behavior for a new query, set `spark.databricks.streaming.realTimeMode.realTimeWatermark.enabled` to false before starting it.
2: Genie Code CLI is managed the same way as Genie Code in the workspace; admins manage one Genie Code budget across the CLI and workspace, and users can apply their free monthly Genie usage in the CLI.
3: IP functions will be available by default for workspaces with the compliance security profile enabled, letting users work with IP addresses and CIDR blocks, including joins on them.
4: Serverless rate limits let you limit Spark executor autoscaling for serverless jobs and pipelines by setting a size on an automated compute object.
5: Governed tag propagation supports classic compute running Databricks Runtime 19 or above, in addition to serverless compute; governed tags on a source propagate to the tables and views derived from it on either compute type.
6: The PostgreSQL integrated CDC pipeline lets you ingest change data from PostgreSQL into Azure Databricks using a single integrated CDC pipeline with no separate ingestion gateway.
7: Budgets scoped to Unity Gateway, including budgets for Genie, support daily per-user thresholds in addition to monthly per-user thresholds; you can set a daily threshold, a monthly threshold, or both, with separate alert, webhook, and block usage actions for each period, and daily thresholds reset at 00:00 UTC.
8: External Iceberg engines can query Unity Catalog views over Iceberg-compatible tables through the Iceberg REST catalog.
9: Providers can add Unity Catalog agent skills to OpenSharing shares and Azure Databricks Marketplace listings; Databricks-to-Databricks recipients get read-only access to each shared skill in the catalog they create from the share, and provider changes reach recipients asynchronously.
10: Cortex AI Function Studio enables organizations to create, evaluate, and optimize production-ready Cortex AI Functions for unstructured and multimodal data workflows, automating prompt engineering, model selection, benchmarking, and optimization.
11: Cortex AI Function Optimization automatically searches across prompts and models for improved implementations of custom AI Functions; using the `AIFUNCTIONOPTIMIZATION` experiment type, customers can evaluate multiple model candidates.
12: You can add `INCLUDE HIERARCHY` to `SHOW GRANTS TO` statements to list the grants held by every role in a grantee's role hierarchy, not only the grants made directly to that role or user.
13: The author migrated the Apache Ossie demo from Streamlit in Snowflake to Snowflake App Runtime as a Next.js app; the Ossie YAML and a Snowflake semantic view kept metric definitions outside the interface, and the demo answered one question with 115,550 without a semantic view versus 103,200 with it.
14: The author benchmarked Snowflake Postgres mirroring for two days on the smallest instance that supports mirroring; new rows show up in `TABLE$live` after ~26 s median and ~37 s p90, regardless of whether the refresh interval is 30 seconds or 10 minutes, and the table lags behind `$live` by up to one refresh interval.
